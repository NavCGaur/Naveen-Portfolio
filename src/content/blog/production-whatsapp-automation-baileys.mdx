When building automated WhatsApp systems—whether for customer support, internal CRM notifications, or EdTech conversational tutors like **LoopLearnX**—getting a "Hello World" bot running on your local machine is easy. Keeping it alive in production is a completely different discipline.

This hub page serves as the complete architectural blueprint for taking a `@whiskeysockets/baileys` WhatsApp bot from a fragile local script to a resilient, production-hardened microservice.

Below is our comprehensive index of real-world engineering guides, structured to help you navigate the exact challenges of deploying Node.js WhatsApp bots on virtual private servers (VPS) while interfacing with serverless APIs (like Next.js on Vercel).

---

## 1. Core Architecture & Deployment

Before writing complex message handlers, you must establish a resilient hosting environment. Standard serverless environments (like AWS Lambda or Vercel) **cannot** run Baileys natively because WebSockets require long-lived persistent connections. You must split your architecture.

    *Our foundational guide covering the split VPS/Vercel architecture, setting up PM2 for process monitoring, handling multi-file authentication state, and establishing basic rate-limited memory queues.*

## 2. Reliability, Reconnects, & Security

Network drops are inevitable. A production bot must handle sudden disconnections without triggering infinite retry loops that result in WhatsApp account bans.
